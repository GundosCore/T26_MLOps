## 5. Личный технический артефакт

Основной личный артефакт — HTTP API для получения предсказаний модели.

Добавлены файлы:

- `src/mlops_team1/api.py`
- `tests/test_api.py`

Также внесены изменения в `pyproject.toml` и `tests/conftest.py`.

Реализованы следующие эндпоинты:

- `GET /healthz` — проверка работоспособности приложения.
- `GET /readyz` — проверка готовности сервиса к обработке запросов.
- `POST /predict` — получение предсказания модели.
- `GET /metrics` — получение метрик приложения.

API загружает модельный bundle через `mlops_team1.model_io.load_bundle`. В ответе на запрос предсказания возвращаются вероятность задержки, бинарный результат, порог классификации, версия модели и `request_id`.

Реализована обработка отсутствующего и некорректного модельного bundle: сервис не должен считаться готовым к обработке запросов, если модель не загружена или повреждена.

## 7. Инженерное решение и выявленный риск

**Риск:** приложение может успешно запуститься как процесс, но не иметь доступной или корректно загруженной модели. В такой ситуации проверка только доступности HTTP-сервера недостаточна: сервис не сможет выполнять предсказания.

**Принятое решение:** разделить проверку работоспособности приложения и проверку его готовности. Эндпоинт `/readyz` проверяет доступность модельного bundle. При отсутствии или повреждении модели возвращается HTTP 503.

Это позволяет не считать неисправный сервис готовым к приёму запросов и использовать readiness-проверку в контейнерной инфраструктуре.
