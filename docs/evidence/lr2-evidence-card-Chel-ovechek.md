## Как проверить

Из корня репозитория выполнить:

```bash
python -m mlops_team1.validate_data --data data/flights_sample.csv --contract data/contract.json --report reports/validation/lr2.json
python -m ruff check .
python -m pytest -q
```

Ожидается: валидатор завершается с кодом `0`, все 10 проверок успешны, Ruff сообщает `All checks passed!`, тесты проходят без ошибок.

[CI для PR #25](https://github.com/GundosCore/T26_MLOps/actions/runs/40192720302/job/121166973805?pr=25)

## Негативные сценарии

- `DepHour = 25` — нарушение диапазона, проверка `ranges`.
- `IsWeekend = 2` — недопустимое значение, проверка `allowed_values`.
- Лишняя ячейка CSV — нарушение проверки `row_length`.
- Дата `2026-1-5` — нарушение строгого формата `YYYY-MM-DD`.

Нарушения данных приводят к коду завершения `1`. Ошибки чтения файла или контракта приводят к коду `2`.

## Обоснование и ограничения

Валидация до обучения позволяет обнаруживать нарушения структуры и качества данных до их передачи последующим этапам обработки.

Прогноз задержки строится за 60 минут до планового отправления. `ArrDelay` — целевая переменная, значение которой становится известно после выполнения рейса, поэтому её нельзя использовать как входной признак модели. Хронологическое разделение данных на train, validation и test помогает снизить риск утечки информации из будущего в прошлое.

Учебный набор содержит 24 строки и подходит для проверки контракта и воспроизводимости тестов, но недостаточен для надёжной оценки качества модели на реальных авиарейсах.
