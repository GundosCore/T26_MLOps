## Задача и личный вклад

Критерий приёмки — после готовности сервиса каждый из четырёх запросов получает ожидаемый статус, а отправленный X-Request-ID совпадает с заголовком и полем `request_id` в теле ответа. При успехе появляется JSON-отчёт. При нарушении контракта скрипт возвращает код 1 и сообщает имя сценария. [Командная задача #96](https://github.com/GundosCore/T26_MLOps/issues/96) · [Личная задача #99](https://github.com/GundosCore/T26_MLOps/issues/99)

Вклад включает `scripts/api_contract_smoke.py` для проверки работающего сервиса, `scripts/export_openapi.py` для экспорта схемы и 16 тестов в `tests/test_api_contract_smoke.py`. Один тест поднимает Uvicorn на свободном порту и проверяет сохранённый отчёт. [PR реализации #104](https://github.com/GundosCore/T26_MLOps/pull/104)

## Живая проверка и инженерное решение

| Сценарий | HTTP | X-Request-ID |
|---|---:|---|
| Корректный запрос | 200 | lr7-valid |
| Час вылета 24 | 422 | lr7-hour-out-of-range |
| Лишнее поле actual_delay | 422 | lr7-unknown-field |
| Час вылета передан строкой | 422 | lr7-wrong-type |

Запрос со строкой `"9"` выявляет неявное приведение типов. Запрос с лишним полем выявляет молчаливое игнорирование данных клиента. Для ответа 422 smoke проверяет стабильный код `validation_error` и непустой список `details`. Сравнение полного текста ошибки сделало бы тест чувствительным к редактуре сообщений. Заданный клиентом X-Request-ID связывает обе части ответа с конкретным запросом.

Экспорт использует сортировку ключей, UTF-8 и переводы строк LF. Два последовательных экспорта дали побайтно одинаковые файлы. Ruff прошёл. До изменений pytest дал `152 passed, 1 skipped`, после — `168 passed, 1 skipped`. Слой project — `48 passed`. [Протокол живого прогона](https://github.com/GundosCore/T26_MLOps/pull/104#issuecomment-7108809449) · [CI на Ubuntu](https://github.com/GundosCore/T26_MLOps/actions/runs/45228658023)

## Внесённый дефект и диагностика

В отдельной копии настройка `PredictionRequest` была изменена с `extra="forbid"` на `extra="ignore"`. Сервис принял запрос `lr7-unknown-field` с полем `actual_delay` и вернул 200 при ожидаемом 422. Тест `tests/test_api_contract_smoke.py::test_smoke_passes_against_real_http_server` упал. После перезапуска сервера CLI завершился с кодом 1 без файла отчёта и вывел:

```text
CONTRACT SMOKE FAILED: unknown_field: ожидался status 422, получен 200
```

Полный прогон с дефектом дал `3 failed, 165 passed, 1 skipped`. Кроме живого smoke упали проверка запрета лишнего поля и проверка схемы OpenAPI. После опыта файл API восстановлен.
